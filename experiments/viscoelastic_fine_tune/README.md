# Полное дообучение FoundNO на viscoelastic_instability_v2

В этой папке находится код обучения, использованный в локальном эксперименте в ноябре 2026 года. Обучение начинается с исходного предобученного `cfno_9_11/core.pt`; все параметры сети разморожены. Чекпоинт, ранее дообученный на Euler, для инициализации не используется.

## Данные и постановка задачи

- Сохраняется официальное разбиение The Well на `train`, `valid` и `test`: **210 / 22 / 22 траектории** в скачанном выпуске v2. Траектории не перераспределяются между выборками и не отфильтровываются.
- Из каждой траектории берутся первые **20 последовательных сохранённых кадров** с индексами `0..19`. На вход подаётся кадр 0, повторённый вдоль временной оси; выход содержит все 20 кадров: восстановление кадра 0 и прогноз 19 будущих кадров.
- Исходные поля `512x512` уменьшаются до `128x128` усреднением по площади и сохраняются в отдельном кэше. Исходные HDF5-файлы не изменяются.
- Физические каналы: `c_zz`, `pressure`, `velocity_x`, `velocity_y`, `C_xx`, `C_xy`, `C_yx`, `C_yy`. Сохраняются обе записанные внедиагональные компоненты тензора.
- Среднее и стандартное отклонение каждого канала рассчитываются только по train. Для обучения и валидации используется одна и та же нормализация.
- В дополнительном входном канале передаётся фактически прошедшее физическое время, делённое на максимальный горизонт train. Интервал между сохранёнными кадрами составляет примерно 1 для AH/CAR/EIT и 4 для переходных режимов; одного номера кадра недостаточно, чтобы учесть эту разницу.

С The Well здесь совпадает только разбиение на выборки. В этом эксперименте по начальному состоянию предсказывается весь пространственно-временной блок. Официальный авторегрессионный бенчмарк использует другую постановку: четыре входных кадра и один выходной кадр.

## Модель и обучение

Предобученное ядро загружается целиком. Из исходных адаптеров переносятся совместимые тензоры Mamba-lifting, столбцы входных весов для координат сетки и скрытый слой выходного адаптера projection. Входные веса для новых физических полей и последний выходной слой на восемь каналов инициализируются заново. У всех **193 030 123 параметров** установлено `requires_grad=True`; исходная архитектура также содержит неиспользуемые параметры обходных связей channel-MLP, которые не участвуют в прямом проходе.

Ядро использует зафиксированные версии исходных модулей из `cfno_upstream/`; их происхождение указано в `cfno_upstream/SOURCE.txt`. Для экономии памяти промежуточные активации пересчитываются при обратном проходе (activation checkpointing), без изменения операций прямого прохода. `ChunkedAdamW` выполняет обычный AdamW в FP32 по частям параметров, разделяющим одно хранилище памяти, включая вещественные и мнимые компоненты весов Фурье.

Параметры эксперимента: размер батча 1, 200 эпох, скорость обучения ядра `1e-4`, скорость обучения адаптеров `1e-3`, weight decay `1e-4` и ограничение нормы градиента значением 1. Функция потерь — MSE по нормализованным данным на всех 20 кадрах. `ReduceLROnPlateau` следит за validation MSE с `patience=12` и коэффициентом уменьшения скорости обучения 0,5; ранняя остановка отключена. Минимальная скорость обучения составляет `1e-7` для ядра и `1e-6` для адаптеров.

VRMSE рассчитывается отдельно для каждой траектории, канала и момента времени:

```text
sqrt(mean_xy((prediction - truth)^2) / (var_xy(truth, unbiased=True) + 1e-7))
```

Итоговый VRMSE прогноза усредняет эти значения по каналам, траекториям и будущим кадрам `1..19`. Чекпоинт `best.pt` выбирается по validation MSE, а `best_vrmse.pt` — по validation VRMSE будущих кадров. Test оценивается после обучения. Скрипт создания GIF также позволяет оценить выбранный по валидации чекпоинт на всей отложенной test-выборке после прерванного обучения.

## Окружение

Проверенное локальное окружение: Ubuntu 24.04 в WSL2, Python 3.10, PyTorch `2.4.0+cu121`, `mamba-ssm==2.2.2`, `causal-conv1d==1.4.0` и RTX 4080 SUPER с 16 ГиБ видеопамяти. Код требует настоящую CUDA-реализацию Mamba; автоматической замены на SimpleSSM нет. Версии остальных пакетов указаны в `requirements.txt`.

Подготовьте совместимое окружение CUDA/PyTorch/Mamba, затем установите зависимости Python:

```bash
cd experiments/viscoelastic_fine_tune
python -m pip install -r requirements.txt
```

## Необходимые файлы

Разместите датасет в `data/viscoelastic_instability_v2/`. Внутри должны находиться папки `data/train`, `data/valid`, `data/test` с исходными HDF5-файлами. Датасет доступен на сайте [The Well](https://polymathic-ai.org/the_well/datasets/viscoelastic_instability_v2/).

Разместите исходные предобученные `core.pt`, `lift_0.pt` и `proj_0.pt` в `pretrained/cfno_9_11/`. Веса модели и датасеты в этот репозиторий не добавляются.

Один раз извлеките совместимые тензоры весов lifting:

```bash
python extract_cfno_lifting_tensors.py \
  --source pretrained/cfno_9_11/lift_0.pt \
  --output pretrained/cfno_9_11/lifting_tensors.pth
```

Скрипт извлечения обрабатывает устаревшие ссылки dill в отдельном процессе и сохраняет только тензоры весов. Недоступные вспомогательные функции старых вычислительных ядер при этом не выполняются. Загружайте только доверенные исходные файлы чекпоинтов.

## Запуск и возобновление обучения

Переносимый конфиг — `cfgs/foundno_viscoelastic_v2_first20_full.yaml`. Пути в нём заданы относительно папки эксперимента; измените их, если хотите использовать уже имеющиеся датасеты и чекпоинты. В конфиге `.wsl.yaml` и скрипте запуска `.wsl.sh` сохранены точные пути исходного локального эксперимента. Этот скрипт обращается к исходной рабочей папке на компьютере Никиты; после клонирования репозитория используйте переносимый скрипт из команд ниже.

```bash
# Подготовить кэш и рассчитать нормализацию только по train, без загрузки модели.
python train_foundno_viscoelastic.py \
  --config cfgs/foundno_viscoelastic_v2_first20_full.yaml --prepare-only

# Выполнить три шага оптимизатора для проверки градиентов, обновления ядра,
# расхода памяти и времени. Обновлённые веса пробного запуска отбрасываются;
# последующее обучение начинается с исходных предобученных весов.
bash run_foundno_viscoelastic_training.sh --smoke-only

# Запустить полное дообучение.
bash run_foundno_viscoelastic_training.sh

# Продолжить с последней завершённой эпохи, восстановив оптимизатор и scheduler.
bash run_foundno_viscoelastic_training.sh \
  --resume runs/viscoelastic_v2_first20_full/latest.pt
```

Чтобы использовать другой интерпретатор, задайте `PYTHON=/path/to/venv/bin/python`. Если в папке результатов уже есть история обучения, требуется `--resume` либо новая папка результатов. После возобновления незавершённая эпоха выполняется заново с последней сохранённой границы эпохи. Состояния генераторов случайных чисел не восстанавливаются, поэтому побитовое совпадение с непрерывным обучением не гарантируется.

Сохраняются `latest.pt`, `best.pt`, `best_vrmse.pt`, `history.jsonl`, `metrics.csv`, `training_curves.png`, validation-метрики каждой эпохи, списки траекторий в выборках, параметры нормализации и сведения об исходных весах модели. Полная эпоха на локальной видеокарте занимала примерно 4–4,5 минуты.

## GIF: истинное решение, предсказание и ошибка

```bash
python make_viscoelastic_gifs.py \
  --checkpoint runs/viscoelastic_v2_first20_full/best_vrmse.pt \
  --output gifs/viscoelastic_v2_best
```

Скрипт выбирает по одной траектории каждого режима в каждой выборке с `seed=42`, без отбора по ошибке предсказания. Создаются 21 GIF со всеми восемью физическими полями, три обзорных GIF для `velocity_y`, изображения для предпросмотра, HTML-галерея и кэш массивов истинных и предсказанных значений. В каждом GIF 20 кадров; шкалы цвета для True/Predict фиксированы во времени. Предсказания на validation проверяются по сохранённым для этого чекпоинта метрикам каждого канала и момента времени.

Процентная ошибка на изображении рассчитывается как `100*abs(pred-true)/max(abs(true),epsilon)`, где `epsilon=max(1% P99(abs(true)),1e-7)` отдельно для каждого поля и траектории. Цветовая шкала ошибки насыщается при 100%; численные метрики не обрезаются. Эта поточечная процентная ошибка отличается от VRMSE.
